# IntraService Admin Panel — Руководство

Веб-панель-администрирование для бота
**[IntraService Telegram Bot](https://github.com/Fifth-Ace/intraservice-telegram-bot)**.
Панель читает внутренние базы бота и показывает живой дашборд; она **не** меняет
заявки в IntraService напрямую и **не** заменяет бота.

Это руководство относится к **Community Edition** панели. Часть действий
(настройка подключения, управление доступом) в бета-версии может находиться в
режиме «чтение»; боевая запись выполняется самим ботом.

## 1. Возможности

- **Живые метрики** из баз бота:
  - операций сегодня (из `audit_log`);
  - средний ответ IntraService API;
  - сколько заявок требует внимания;
  - «заведено по каналам» — Telegram / Почта / Вручную;
- **Очередь обработки**: заявки, ожидающие подтверждения, и действие «Отменить»;
- **Статус-лампочки** транспорта (Official API, Playwright fallback) и сервисов
  (Telegram intake, Mail watcher, AI analyzer);
- **Журнал событий** и диаграмма операций по источникам;
- **Настройка подключения**: параметры IntraService и Telegram;
- **Настройка доступа**: кто (ФИО + Telegram ID) может пользоваться ботом;
- **4 темы** (Aurora, светлая, тёмная, минимализм);
- **Маршрутизация по хэшу** — у каждой страницы свой адрес, работает
  «назад/вперёд» и переживает перезагрузку.

## 2. Требования

- Node.js **≥ 22.5**;
- CLI `sqlite3`, доступный на хосте (панель читает базы через него в
  read-only режиме);
- развёрнутый **intraservice-telegram-bot** (или пустая заглушка для просмотра
  интерфейса).

## 3. Установка

Разместите панель и бота **в соседних каталогах**:

```
parent/
├── intraservice-server-bot/     # Telegram-бот
└── intraservice-admin-panel/    # данная панель
```

```bash
cd intraservice-admin-panel
npm install
```

Зависимостей времени выполнения нет — установка опциональна, но рекомендуется
для единообразия. Создайте учётную запись администратора:

```bash
npm run bootstrap-admin
```

Скрипт читает начальный пароль интерактивно (без вывода на экран) и **откажется
перезаписывать** уже существующий `data/auth.json`.

## 4. Настройка окружения

По умолчанию пути к базам бота разрешаются относительно панели из соседнего
каталога `../intraservice-server-bot`. Если бот лежит иначе — укажите путь
переменными окружения.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PANEL_BOT_DIR` | `../intraservice-server-bot` | корень каталога бота |
| `PANEL_BOT_DB` | `<бот>/data/intake.sqlite3` | база intake / аудита |
| `PANEL_MAIL_DB` | `<бот>/data/mail_watcher.sqlite3` | база mail-наблюдателя |
| `PANEL_HOST` | `0.0.0.0` | адрес прослушивания |
| `PANEL_PORT` | `9120` | порт |
| `PANEL_AUTH_FILE` | `data/auth.json` | хранилище учётной записи |
| `PANEL_TRUST_PROXY` | `0` | `1` за доверенным реверс-прокси |

Пример переменных для systemd: см. `systemd/intraservice-admin-panel-preview.service`
и `.env.example`.

## 5. Запуск и проверка

```bash
npm run check   # синтаксическая проверка всех файлов
npm test        # самопроверка авторизации
npm start       # запуск панели
```

Панель слушает по умолчанию на `0.0.0.0:9120`. Проверка работоспособности:

```bash
curl http://127.0.0.1:9120/healthz
# {"ok":true,"mode":"authenticated-live","authConfigured":true}
```

## 6. Разделы интерфейса

| Раздел | Назначение |
|---|---|
| Дашборд | Ключевые метрики, очередь, статусы сервисов, диаграмма |
| Операции | Операции по источникам (Official API / Playwright / …) |
| Очереди | Заявки, ожидающие подтверждения, и кнопка «Отменить» |
| Сервисы | Состояние транспорта и сервисов (лампочки) |
| Журнал | Аудит событий (без персональных данных) |
| Настройки | Вкладки: Дашборд, Основное, Доступ, Подключение |

## 7. Маршрутизация

| Страница | Адрес |
|---|---|
| Дашборд | `#/` |
| Операции | `#/operations` |
| Очереди | `#/queue` |
| Сервисы | `#/services` |
| Журнал | `#/log` |
| Настройки | `#/settings` |
| Настройки → Основное | `#/settings/basic` |
| Настройки → Доступ | `#/settings/access` |
| Настройки → Подключение | `#/settings/connect` |

Переход по меню меняет адрес; перезагрузка страницы остаётся на том же разделе;
кнопки «назад/вперёд» браузера работают.

## 8. Темы оформления

Переключатель тем — в правом верхнем углу и в разделе «Настройки → Дашборд».
Варианты: **Aurora**, **Светлый**, **Тёмный**, **Минимал**. Выбор запоминается в
`localStorage`.

## 9. Подключение к боту

Раздел «Настройки → Подключение» (маршрут `#/settings/connect`) показывает
параметры двумя группами:

- **Настройки IntraService** — адрес системы, логин, пароль (пароль — скрытый
  ввод);
- **Настройки Telegram** — токен бота (скрытый ввод), Chat ID администратора.

Токен и пароль приходят из базы бота **замаскированными** (виден только факт
«задан/не задан») и никогда не выводятся в ответах и логах. Если значение уже
задано, поле пароля/токена оставляют пустым — при сохранении оно не
перезапишется.

## 10. Очередь и отмена заявки

Раздел «Очереди» показывает заявки в статусах `preview` и
`needs_clarification` (ожидают подтверждения создания). Действие **«Отменить»**:

- является точным зеркалом двух обновлений самого бота;
- разрешено только для не-созданных заявок;
- **не** затрагивает уже созданные заявки (с `intra_id`) — их закрытие —
  прерогатива бота;
- требует сессии и CSRF-токена.

## 11. Запуск через systemd

В каталоге `systemd/` лежит пример юнита. Уточните рабочие пути под свой
профиль (в публичной версии используется `/opt/intraservice-admin-panel`):

```ini
[Service]
Type=simple
WorkingDirectory=/opt/intraservice-admin-panel
ExecStart=/usr/bin/node server.mjs
Environment=PANEL_HOST=127.0.0.1
Environment=PANEL_PORT=9120
Environment=PANEL_TRUST_PROXY=1
Restart=on-failure
```

Затем:

```bash
cp systemd/intraservice-admin-panel-preview.service ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now intraservice-admin-panel-preview.service
systemctl --user status intraservice-admin-panel-preview.service
```

## 12. Обновление

```bash
git pull origin main
npm run check
systemctl --user restart intraservice-admin-panel-preview.service
```

После обновления `data/auth.json` сохраняется (он в `.gitignore`), пароль не
сбрасывается.

## 13. Данные и резервное копирование

Панель **не создаёт собственных данных** о заявках — она читает базы бота.
Для резервного копирования достаточно сделать копию базы бота
(`intake.sqlite3`, `mail_watcher.sqlite3`) штатными средствами бота (например,
`safe-backup` самого бота). Хранилище учётной записи панели — `data/auth.json`
(продублируйте при переносе).

## 14. Тестирование

```bash
npm run check        # синтаксис server.mjs, auth.mjs, tools/*
npm test             # auth-self-test: вход, CSRF, logout — не трогает данные
```

Тесты не создают и не изменяют заявки в IntraService.

## 15. Решение проблем

### Панель не стартует / ошибка чтения базы

- Убедитесь, что `sqlite3` доступен в `PATH`.
- Проверьте, что переменные `PANEL_BOT_DB` / `PANEL_MAIL_DB` указывают на
  существующие файлы.
- Для read-only чтения используется `-readonly`; права на файл должны позволять
  читать процессу панели.

### `/api/config` и разделы настроек пусты

- Панель не может прочитать `config.json` или `intraservice.env` бота — проверьте
  `PANEL_BOT_DIR`.
- Секреты намеренно маскируются: пустое поле пароля/токена означает «значение не
  задано» или «значение скрыто».

### Кнопки «Отменить» неактивны / не работают

- Действие требует залогиненной сессии и CSRF-токена.
- Отменять можно только `preview` / `needs_clarification`; у созданных заявок
  кнопки нет.

### Обновление сбрасывает на главную

- Убедитесь, что используется hash-router (адреса вида `#/queue`). Если адрес
  обновляется до `#/queue` — панель остаётся на разделе.

### Лампочка «не горит», хотя текст «online»

- Статус точки зависит от реальной активности сервиса (наличие операций за
  период), а зелёный/жёлтый/серый отражают: работает / резерв(Playwright) /
  молчит. Смотрите подпись рядом с лампочкой.

### Порт 9120 занят

- Укажите другой порт переменной `PANEL_PORT`. Проверка: `ss -ltnp | grep 9120`.

## 16. Безопасность

- учётная запись администратора: начальный пароль при `bootstrap-admin`, на
  диске — только `scrypt`-хэш;
- обязательная смена пароля перед входом;
- 8-часовые сессии в `HttpOnly` / `SameSite=Strict` cookie;
- CSRF-защита всех изменяющих запросов;
- ограничение попыток входа и временная блокировка;
- строгие заголовки безопасности + `Cache-Control: no-store`;
- приватные/секретные значения не выводятся в журналы и ответы.

Приём и смена пароля возможны только при HTTPS, с loopback, либо когда доверенный
прокси заявляет `X-Forwarded-Proto: https` (`PANEL_TRUST_PROXY=1`). Не включайте
`PANEL_ALLOW_INSECURE_AUTH=1` вне изолированных тестов.

## 17. Текущие ограничения

- бета: настройка подключения и управление доступом в публичной версии могут
  быть read-only;
- панель не выполняет мутации IntraService;
- почтовая очередь считается по уникальным заявкам в `mail_watcher.sqlite3`
  за последние сутки;
- маршрутизация на hash-ядре (совместимо с любым статическим хостингом без
  серверных rewrite-правил).

```
├── package.json

└── .gitignore
```
